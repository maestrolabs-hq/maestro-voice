# Framework alignment

Read with the [security entry](../security-boundaries.md), [engineering baseline](../../engineering-baseline/engineering-baseline.md), and [security enforcement matrix](security-enforcement-matrix.md). This table maps relevant alignment, not complete framework coverage. Selected verification scope, policies, target levels, thresholds, and response windows are required project bindings; links and reports supply no authority.

| Framework | What it is | Application here | Implementing IDs |
| --- | --- | --- | --- |
| [OWASP Top 10:2025](https://owasp.org/Top10/) | Web application risk awareness | Review applicable risks at boundaries; prevent injection, unsafe defaults, and access-control failures; verify with tests | SDL-001, SDL-002, SDL-003, SDL-004, SDL-005, SST-001, SST-008; P-011, P-013, P-014 |
| [OWASP ASVS 5.0.0](https://owasp.org/www-project-application-security-verification-standard/) | Application security verification requirements | Bind applicable verification scope and rigor to authentication, input, cryptography, data, and security tests; no verification level is inferred | SDL-003, SDL-004, SDL-005, SDL-006, SDL-007, SDL-008, SDL-009, SST-001, SST-007, SST-008 |
| [OWASP SAMM 2.0.3](https://owasp.org/www-project-samm/) | Software assurance maturity model | Structure governance, design, implementation, verification, and response improvement without scoring maturity | SDL-001, SST-012, SCH-001, VR-008; FND-001, ENF-010, C-006 |
| [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/llm-top-10/) | LLM application risk taxonomy | Map prompt injection, excessive agency, output handling, disclosure, and model/tool supply chains; assess remaining categories explicitly | SDL-011; SEC-001, SEC-002, SEC-004, SEC-005; SCH-005, SCH-011; P-014 |
| [NIST SSDF version 1.1, SP 800-218](https://csrc.nist.gov/projects/ssdf) | Secure software development practices | PO Prepare the Organization: engineering baseline and governance; PS Protect the Software: source and artifact integrity; PW Produce Well-Secured Software: secure design and verification; RV Respond to Vulnerabilities: intake, remediation, and root-cause learning, including RV.3 | PO: FND-001, ENF-010, C-001, C-006; PS: SCH-001, SCH-002, SCH-005, SCH-006, SCH-008; PW: SDL-001, SDL-003, SDL-005, SST-001, SST-002, SST-007, SST-012; RV: VR-001, VR-003, VR-004, VR-008, VR-009 |
| [NIST CSF 2.0](https://www.nist.gov/cyberframework) | Cybersecurity risk-management functions | Govern: policy and authority; Identify: threat and component/data inventories; Protect: boundaries and supply-chain controls; Detect: scans and events; Respond: private intake and coordinated remediation; Recover: verified fixed releases and follow-up, not an operational recovery system | Govern: ENF-010, C-006, SEC-004; Identify: SDL-001, SDL-009, SCH-011; Protect: SDL-005, SDL-006, SCH-005, SCH-006; Detect: SDL-008, SST-001, SST-002, SST-003; Respond: SEC-007, VR-001, VR-003, VR-007; Recover: VR-004, VR-006, VR-008, SCH-013 |
| [SLSA specification 1.2](https://slsa.dev/spec/) | Build Track and Source Track supply-chain integrity requirements | Bind Build Track target level and verified provenance; map applicable Source Track controls to protected source and immutable releases; evidence does not imply a level | SCH-001, SCH-002, SCH-005, SCH-006, SCH-008; ENF-007 |
| [CWE Top 25 Most Dangerous Software Weaknesses, current edition](https://cwe.mitre.org/top25/) | Prioritized weakness reference | Review applicable weakness classes, map triage to CWE, and search for similar root causes | SDL-004, SST-001, SST-007, VR-003, VR-008 |
| [OpenSSF Scorecard](https://scorecard.dev/) | Automated repository security-practice signals | Optional informational/report-only analysis per profiles; no score floor or inferred merge safety | SCH-012, SEC-008 |
| [Sigstore](https://www.sigstore.dev/) | Signing and identity-based verification ecosystem | Profile-selected signing/verification with bound trust, identity, revision, and artifact subjects | SCH-001, SCH-002, SCH-013 |
| [SPDX](https://spdx.dev/) | Software bill of materials standard | Produce and verify one of the required SBOM formats, including dependency and license metadata | SCH-003, SDL-010 |
| [CycloneDX](https://cyclonedx.org/) | Software bill of materials standard | Produce and verify the other required SBOM format with artifact association and completeness checks | SCH-003, SDL-010 |
| STRIDE | Threat-model taxonomy: spoofing, tampering, repudiation, information disclosure, denial of service, elevation of privilege | Analyze feature trust boundaries beside ADRs and revisit changed boundaries | SDL-001, SDL-011; SEC-002, SEC-003, SEC-004, SEC-005, SEC-006, SEC-007, SEC-008, SEC-009 |

This is alignment, not certification; no assessment, attestation or SAMM maturity score is claimed.
